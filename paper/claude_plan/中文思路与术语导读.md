# 《Charging Ahead》中文思路与术语导读

对应 `paper/claude_plan/latex/main.tex` 的英文论文，说明日期为 2026 年 10 月 24 日。
这份导读用于理解论文，不是另一份模型结果，也不计入英文论文页数。

## 一句话抓住整篇文章

**先用原有公交时刻表确定“怎样换车才能不减少服务”，再从具体车辆安排推出电池、充电、减排和成本，最后把换车分成十年，并在另外两座城市检验同一套方法。**

这里有一条连续的逻辑链：

时刻表 → 柴油基准 → 电车调度与选站 → 行驶里程和充电需求 → 环境与财务账 → 十年转换顺序 → 三城比较 → 面向官员的建议。

论文标题中的 **Charging Ahead** 利用了 charge 的“充电”和 charge ahead 的“向前推进”两层意思；**Two-Constant** 指电车调度主要由续航 R 与充电时间 T 两个常数描述；**Timetable-Preserving** 指保留既定班次及其时间；**Transition** 指逐步转换公交系统。

## 逐章读懂它在做什么

### 摘要页 Summary Sheet

给评委快速交代问题、模型、主要数值、验证和限制。摘要不是背景介绍的缩写，它应直接告诉读者“我们做了什么，得到什么，在什么条件下成立”。

本文把温哥华作为主要案例，芝加哥、伦敦作为方法迁移案例。主情景采用可用续航 270 km、每次充电 60 min。温哥华代表日需要服务 19,967 个班次；柴油最低车辆数为 1,043，找到的电车可行方案为 1,247。跨全部 25 种服务模式，最多需要 1,256 辆在用电车。

“代表日 1,247”和“全部测试日最大值 1,256”回答不同问题，不能互相替代。

### 第一章：问题、证据与研究范围

原题要回答四件事：换成电车有哪些生态影响、经济上怎样、如何在 2033 年前逐步转换、如何向交通官员解释建议。

我们首先规定“保留服务”的含义：每个纳入的班次都按原出发和到达时间运行一次；电车与柴油车容量视为相同。这保留了模型中的服务供给。没有逐班乘客数据，就不能进一步声称已经解决拥挤问题。

另一个重要边界是“零排放电源”。电车没有排气管排放，并不说明发电和造电池没有排放。本文因此分开讨论平均电网供电和有条件的零排放来源供电。

2023 是服务数据和题目的年份；这是一项在 2026 年整理证据的回顾性研究，不假装后来的资料在 2023 年已被掌握。

### 第二章：数据、假设与符号

核心数据是 GTFS 公交时刻表。它告诉我们何时从哪里出发、何时到哪里。它不是车辆的实际 GPS 轨迹，也不直接告诉我们每辆实体公交如何排班。

有证据的数据和人为设定要分开。班次时间来自公开时刻表；部分距离是从数据推导的；空驶速度、道路绕行系数、同容量车辆等属于建模假设。电价和维护费也有明确的假设部分。

R 是**可用续航**，不是宣传材料里的理想标称续航；T 是模型假设的一次固定充电占用时间。即使没有把电耗完，模型也安排 T 分钟来充满，能量账只计实际补进去的电。

续航与充电时间还能推导物理规模：每公里电耗乘 R 得到可用电池容量，再考虑允许使用的电量比例，得到标称容量。以本文参数计算，标称电池为 540 kWh；考虑充电损耗后，电网侧功率为 480 kW。kWh 是能量，kW 是功率，不能混用。

### 第三章：先把“车如何接班次”算清楚

先想象一辆公交跑完班次 i，还要接班次 j。它不能瞬移，所以两班之间要留出开到下一起点的时间。电车还必须有足够的电。

有两种接法：直接开到下一班起点；或者先去充电站，充电，再去下一班起点。后者的三段时间——去充电站、充电、离开充电站——都要算；两段绕行距离也都消耗续航。

**P1** 是“充电节点已经选好，安排车辆”；**P2** 是“还要决定选哪些节点，再安排车辆”。车越少通常采购越省，节点位置也会影响车能否及时继续工作。

柴油基准暂时不受续航和充电限制。把可以连续执行的两个班次连起来，尽量让更多班次串在同一辆车上。最大匹配提供准确的柴油最小车辆数：班次数减去最大匹配数。这个“准确”仅指论文给定的简化条件，仍没有包含现实的多车场、司机或车型限制。

电车问题复杂得多，所以大规模实例用启发式：先拼成一段段不超续航的班次块，再通过充电把这些块连接成车辆任务，同时尝试不同节点。它找到的是能执行的方案，不保证是所有可能方案中用车最少的那个。

**参考程序的修正**：不能只检查“块 A 能接 B、B 能接 C”。电车从充电站开到 B 起点已经耗了电；跑完 B 后再去下一充电站，这些距离必须放在同一笔续航账上。论文用一个 3 + 7 + 3 = 13 km、超过 10 km 续航的反例解释问题。

独立验证器会从输出任务重新模拟每个班次、转场、充电和剩余续航，检查是否漏班、重复、迟到或超续航。小实例还会用精确求解比较：300 个测试里，改进方法有 252 个达到已证明的最优值，观察到的最大差距是 2 辆。这不是任何城市、任何规模都最多多用 2 辆的保证。

### 第四章：温哥华调度结果

温哥华不只测一个工作日，而是分别测 25 种服务模式。模式相当于一类共同的运营日安排，例如某些工作日、周末或特殊日期。它们在 119 天日历中有不同出现次数。

结果说明，在给定假设下确实能覆盖纳入的时刻表。但 1,256 不是温哥华现实公交总数：它不含备用车，电车车型被统一化，部分无轨电车代理服务单独保留，也没有证明车辆能在连续两天之间及时归位并充好电。

选中的“充电节点”是数学图中的站点位置，不等于已有土地和电力许可的真实充电站。某一节点竟需最多 197 个同时充电位置，恰好暴露了无限充电桩假设的工程局限。四个节点绝不等于只需要四根充电桩。

敏感性分析会改变续航、充电时间和距离假设，观察需要多少车。理论最优值在续航放宽时不应变差；启发式搜索却可能找到更差的安排，所以论文保留并重新验证先前可用的方案。

### 第五章：环境账

环境账从调度输出的总里程出发。柴油车按里程和排放因子算运行排放；电车按电耗、充电效率和电网排放因子算运行排放，还计车辆与电池生产、后续电池更换。

CO₂e 是把不同温室气体折算成二氧化碳当量；NOₓ 和 PM₂.₅ 是另外的空气污染物，不能和 CO₂e 相加。

温哥华主情景下，一开始就替换并运行十年的比较，平均电网口径避免约 1,416.2 kt CO₂e，即约 141.62 万吨；条件性零排放电源情景约 1,438.1 kt。这里比较的是统一的化石柴油假想方案，不是准确复原温哥华真实混合燃料车队。

不能把它称为覆盖所有环节的完整生命周期评估：道路和站点施工、处置、非尾气颗粒等尚未全部纳入。本文是有明确边界的车辆生产与运行比较。

### 第六章：财务账

CAPEX 是前期买车、建充电设施的钱；运行费包括能源和维护；电池到了寿命还要更换。十年结束后仍能继续使用的车身、电池和设施，不能一律当作没价值，所以两边都计期末资产价值。

不同年份的钱要折算到同一时点，叫折现。本文金额按不变的 2023 年加元计算，采用 3% 实际折现率。NPV 在本文特指**相对柴油方案的净现值节省**：正数表示公交机构更省钱，负数表示更贵。

温哥华即时替换比较中，补助为 0%、25%、50% 时，NPV 节省分别为 -8,030 万、1.598 亿、3.999 亿加元。补助比例是针对论文定义的“正的初始资本增量”，不是所有十年成本，也不是已获批的真实补助政策。

补助改善公交机构的负担能力，但不会让生产车辆或修建设施实际消耗的社会资源自动变少。

财务结果的一个重要弱点是柴油基准只优化“最少多少辆车”，没有同时优化“最低空驶成本”。若给予柴油更有利的零空驶成本界，25% 补助下的节省会从 1.598 亿降到约 50 万加元。因此不能将中央情景写成稳健的确定收益。

TCO 是单位车辆公里的折现总成本。两边各自总里程不同，因为空驶不同，所以电车单位公里更便宜，不一定意味着整套电车系统的总支出也更少。

### 第七章：十年转换路线图

论文先用“每辆电车承载的服务里程”和电车相对柴油的车辆需求比，为线路排一个顺序，优先转换较有服务效率的线路组。由于缺少实体车辆对应线路的年龄信息，这不能叫真实的按车龄淘汰顺序。

Nested-route 的 nested 是“集合逐年包含前一年”，不是“公交线路嵌套运行”：今年变电动的线路，明年仍保留，再增加新的线路。

每年对新增后的电车线路集合重新排班，对剩余柴油线路也重新排班。Stock 是已经购置的车辆存量；不能因为某年重新组合后少需几辆，就凭空把已购车辆抹掉。因此用历史最高需求来决定累计购车。

到 2033 年，纳入的班次都交由电车执行。表格给出的是“要这样做需要多少钱”，而不是“在已确认的逐年预算上限下，已经证明做得到”。夜间周转、设施容量、施工进度和备用车仍是执行条件。

这一逐步转换方案与第六章“一开始就全部替换”的对照实验不同。阶段转换的减排估计约 875.4 kt，不能把即时替换的 1,416.2 kt 直接写成阶段方案的减排量。

### 第八章：芝加哥和伦敦

两座城市使用回收的真实 2023 时刻表，套用同一套程序。代表日柴油/电车数量分别为：芝加哥 1,151/1,434，伦敦 6,755/7,383。测试周最大电车需求另为 1,436、7,401。

它检验“方法能否迁移”，没有证明“伦敦天然最适合电车”。两城的成本、能耗、电网因子沿用统一参数，距离还使用停站折线的推算值，数据季节、覆盖范围和车型也不同。

伦敦四个候选节点集中在 169 米范围内，工程上可能只是一个充电片区；不能写成四座已经具备建设条件的独立站。实际运营商库存、备用车和模型在用车辆需求也不能直接混为购车数量。

### 第九章：优点与局限

优点是班次能逐一核查、绕行耗电没有漏算、小例子能和精确答案比较、里程和能量与财务账能够衔接。

局限包括统一车型、假设转场距离和速度、无限充电容量、单日满电开始、没有连续多日车辆闭合、启发式不保证最优、本地报价及建设资料不足。论文要让结论的强度与证据相称。

### 第十章：给官员的信

把技术结果翻译成决策语言：建议从哪些可检验的步骤着手、车辆和资金大致是什么量级、采购前要补哪些资料。它应明确要求先落实场站、电力、冬季测试和实际车辆清单，再释放采购。

### 参考文献与 AI 使用报告

参考文献让读者追查数据和方法。AI 报告披露 AI 做过哪些工作，以及使用的原始提问和输出。现有 Claude 规格和参考程序不能代替完整对话；目前报告仍不完整。这不阻止学习和编辑，但不能声称正式披露材料已经齐备。

## 常见词语速查

| 英文词语 | 本文意思 | 容易误解的地方 |
|---|---|---|
| trip | 一个有确定起终点和时间的班次 | 不是一整条线路，也不是某辆实体车 |
| route | 公交线路 | 一条线路每天可有很多 trip |
| timetable / schedule | 时刻表；也可指车辆安排，需看上下文 | timetable 更强调原有发到时刻 |
| duty | 一辆车一日执行的班次、空驶、充电序列 | 这里不等于司机劳动排班 |
| range block | 一次充电之间可连续执行的一段任务 | 不是街区，也不是行政区 |
| deadhead | 不载客的调车、转场或充电绕行 | 不创造服务里程，但耗时、耗电、花钱 |
| pullout / pullin | 车辆从车场出库、回库 | 本调度边界暂未纳入 |
| usable range R | 实际允许使用的续航 | 区别于厂商标称最大值 |
| charge duration T | 一次充电占用的时间 | 本模型固定为 T，不随补电量缩短 |
| SOC, state of charge | 电池荷电状态，即剩余电量比例 | 本调度主要用已用里程表示相应状态 |
| node | 图上的站点位置 | 不自动等于真实可建场站 |
| station / site | 充电位置或场地 | 一个 site 可以需要许多 plugs |
| plug / charger position | 同时给一辆车补电的位置 | 四个 nodes 不等于四个 plugs |
| graph / arc / edge | 兼容关系组成的图及其连接 | 是数学关系，不一定是实体道路 |
| matching | 给兼容班次配对，使连接不相互冲突 | 不是用相关性“匹配相似路线” |
| path cover | 用若干车辆路径覆盖所有班次 | 最少路径数对应简化柴油最少车辆数 |
| PVR | 同一时刻正在服务的班次最多有多少 | 只是一条下界，还没考虑转场和充电 |
| EVSP | 电动车辆调度问题 | 全称 Electric Vehicle Scheduling Problem |
| BEB | 电池电动公交 | 区别于依靠架空电线供电的无轨电车 |
| DAG | 有向无环图 | 班次按时间连接，不能绕回到更早的班次 |
| P1 / P2 | 已选站后的调度 / 同时选站和调度 | 是本文定义的问题编号，不是通用车型 |
| baseline | 比较基准 | 本文的柴油最小车数不是现实库存 |
| counterfactual | 为比较而设定的“如果继续用柴油”情景 | 不应称为已经发生的事实 |
| constraint | 必须满足的规则 | 如不迟到、不超续航、节点数不超 K |
| objective | 希望最小化或最大化的量 | 本调度主要是尽量少用车 |
| feasible | 满足模型的所有约束 | 不代表已获得现实工程许可 |
| optimal | 在给定模型中最好且有依据证明 | 大规模电车结果未声称达到全局最优 |
| heuristic | 用有针对性的搜索规则寻找好方案 | 快，但可能漏掉更好的方案 |
| lower bound | 最好结果不可能低于的界 | 柴油下界不等于电车最优答案 |
| feasible upper bound | 已找到方案的车辆数，最小需求不会高于它 | 不是需求永远不会超出的工程上限 |
| optimality gap | 可行解与最优值或下界之间的差距 | 仅通过可行性检查不能证明 gap 为零 |
| incumbent | 当前已找到、可以保留的可行方案 | 参数放宽后也需重新验证 |
| MILP | 混合整数线性规划，可含 0/1 选择 | 只有成功证明 optimal 才当作精确答案 |
| LP relaxation | 把整数选择放宽为连续值的线性规划 | 可给下界，但通常不是可执行车队 |
| replay / validation | 重新模拟并检查输出 | 与搜索程序生成答案是不同环节 |
| service pattern | 一类实际运营日的班次集合 | 25 类不等于只观测了 25 个连续日期 |
| annualization | 用一季或一周的频率外推全年 | 不是全年实际观测 |
| capacity | 车辆可提供的乘客容量 | 本文相同容量是设定，未验证拥挤 |
| proxy | 缺少直接测量时的替代量 | 例如某个容量类别不能直接证明动力类型 |
| transferred parameter | 从另一情境借用的参数 | 不是已经核实的本地价格或性能 |
| sensitivity analysis | 改变参数看结果受多大影响 | 单因素变化不是统计置信区间 |
| screening / screen | 用于初步筛查的估算或比较 | 不能翻译成已验证的商业预测 |
| scope / boundary | 研究覆盖什么、计算纳入哪些环节 | 决定结论能用于什么问题 |
| homogeneous | 车辆视为同容量、同类参数 | 不等于现实车队实际只有一种车型 |
| lifecycle | 生命周期 | 本文没有覆盖全部生命周期环节 |
| embodied emissions | 制造车辆和电池时产生的隐含排放 | 发生在生产环节，不是行驶尾气 |
| emission factor | 单位里程或单位电量的排放系数 | 必须连同单位与来源使用 |
| grid intensity | 每 kWh 电力对应的温室气体排放 | 电网平均低碳不等于已采购零排放电源 |
| zero-tailpipe | 车辆行驶时没有排气管排放 | 不等于发电和制造都零排放 |
| CO₂e / kt | 二氧化碳当量；千吨 | 1 kt = 1,000 吨 |
| kW / kWh / GWh | 功率 / 能量 / 百万 kWh | 能量除以时间才是功率 |
| CAPEX / OPEX | 资本支出 / 运行支出 | 购车、设施与日常能源维护分开 |
| grant / eligible cost | 补助 / 模型定义的可获补助成本 | 不是已经批准的项目金额 |
| gross / net | 扣补助前总额 / 扣除相关项后的净额 | 看每个表的具体定义，别只凭单词猜 |
| present value, PV | 不同年份金额折算到同一时点的现值 | 不能直接与未折现总和混用 |
| NPV savings | 相对柴油的净现值节省 | 本文正数为更省，负数为更贵 |
| discount rate | 折现率 | 本文用实际利率配合不变价 |
| constant 2023 CAD | 按 2023 年购买力表示的加元 | 并不是所有支出发生在 2023 年 |
| TCO | 单位车辆公里的折现总成本 | 分母不同，不能只看单位值推断总成本 |
| terminal value | 十年期末尚存的资产价值 | 不同于每年的运营现金节省 |
| payback | 累计收益覆盖投入的时点 | 未来换电池后还应保持不再转负 |
| roadmap / stage | 转换路线图 / 某年的阶段 | 不自动等于有资金保证的施工计划 |
| nested routes | 逐年扩大、保留旧成员的线路集合 | 不是交通路线空间上的套叠 |
| stock / cohort | 已购存量 / 按购入年份或车龄分的群组 | 与某天正在运营的车辆数不同 |
| inventory / active fleet | 登记总库存 / 完成时刻表的在用车队 | 前者可能含备用与维修车辆 |
| implementation gate | 推进采购或施工前必须满足的条件 | 如先落实可用电力、冬季续航 |
| conditional | 只有明确条件满足时结论才成立 | 不应在摘要里把条件全部删掉 |

## 讲给别人时可以用的版本

“我们没有直接假设换成电车一定更环保、更省钱，而是先从原有时刻表出发，安排每辆车跑哪些班、何时充电。柴油车没有充电限制，先求出它至少要多少辆；电车再加入续航和充电约束，找到能保留所有班次的安排。接着，按这些安排真正产生的里程、电量、车辆和充电设施需求计算环境与财务结果，再将线路分十年转为电动。最后在芝加哥和伦敦验证方法可以迁移。结论是，在这组设定下可以构造服务不减少的电车安排，但现实建设仍须验证场站容量、电力、车型和预算；经济收益也不是无条件保证。”
