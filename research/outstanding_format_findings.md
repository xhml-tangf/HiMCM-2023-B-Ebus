# HiMCM 其他年份 Outstanding 论文与官方示例：格式研究

调查日期：2026-10-18。范围：只查找其他年份的 HiMCM Outstanding 论文、节选或官方评语；**没有检索、打开或下载任何 2023 年 HiMCM B 题外部论文**。本文只读审查了本项目的 current manuscript（paper/ebus_transition.tex 和 paper/ebus_transition.pdf），没有修改论文。

## 结论摘要

1. **没有找到可公开下载且可验证的 2025 HiMCM 获奖队完整论文。** COMAP 2025 结果页公开列出 8 个 Outstanding 队，并链接 Problem A/B 结果 PDF；Mathmodels 也明确列出 2025 A 题 5 篇、B 题 3 篇学生论文，但正文和 commentary 都要求 Mathmodels Membership。公开能核验的只有题目、获奖控件号和论文数量。
2. **公开可得的最强正式材料是 2024 HiMCM Examples（45 页）和对应 Judges' Commentary。** 示例 PDF 是 COMAP 按评审维度挑选、拼接的页级摘录，不等同于一份或八份完整论文；其中既有 Outstanding 页，也有非 Outstanding 页，不能整档标成 “Outstanding 论文合集”。
3. 2024 结果页可交叉确认示例中的 Outstanding 控件号。与当前题最相关的可读 Outstanding 例证包括：Team 15504 的 summary/conclusion、Team 15926 的 summary/letter、Team 15041 的跨情境评价表、Team 14995 的模型比较与稳健性、Team 16226 的流程图和 assumptions。
4. 当前稿的定量、来源追溯和敏感性工作明显超过示例平均水平；主要格式缺口是**缺少独立的 Assumptions、Validation、Conclusions 三个结构块**，模型直到 PDF 第 7 页才开始，且图 1、图 3 各自占掉一整页。另有 summary 信息过密、部分关键范围在图与正文中对应不清、高成本结论与“继续推进”建议之间的决策逻辑不够直白等问题。

## 从 Outstanding 页与评委评论提炼出的写作规律

### 1. Summary 是决策摘要，不只是背景与模型简介

2024 评委评论要求 summary 覆盖问题、建模过程、关键数值结果和建议，并提醒不要在 summary 里只重复问题。Team 15504 和 15926 都先说明问题被怎样操作化，再交代模型、验证与具体输出，最后给应用或限制。

对当前稿的直接含义：现有 summary 已经有问题、模型、结果、建议和 caveat，但四问覆盖不够显式，引用标记很密，读者需要越过很多“未验证/边界”语言才能看到主结论。可改成 5 个自然段或清晰短块：四问应答 → 主模型 → 关键数值 → 验证 → 决策；引用移到正文，把最重要结果提前。

### 2. 最佳结构不是“证据清单 → 若干公式 → 大量结果”，而是可追踪的建模链

评委评论总结的路径是：清晰问题重述 → 有组织的目录 → assumptions with justifications → 变量定义 → 基础模型 → 应用与数学支持 → 敏感性 → strengths/limitations → 明确 conclusion。

Team 16226 先用一个相对简单的 base model，再逐步加入 energy mix、forecast 和额外环境影响的复杂度；评委明确称赞这条连续建模链。Team 15504 则从“sport inclusion”抽象成 binary classification，再建立由三部分组成的概率模型，使问题、假设、变量和输出彼此对应。

当前稿的结构是 Problem → Evidence audit → Fleet model → Cost/environment → Results → Sensitivity。模型链条本身存在，但证据审计占了 PDF pp.3–6，到 p.7 才进入决策变量；读者会先看到大量数据更正，再看到模型。建议把审计缩成“关键可用性表 + 三段审计结论”，将完整来源核查留在 repository，正文先给出任务、假设、模型框架和数据边界。

### 3. Assumptions 必须少而有用，并且能追到具体公式或结果

2024 评委评论说得非常具体：最成功的稿子既列 assumption/justification，又在模型和敏感性分析中再次说明它用在哪里。Team 16226 的线性能耗假设随后直接影响全容量、平均利用率和能量需求的计算。

当前稿解释了 capacity signature、normal renewal、exclusive fuel boundary、no refuelling within a duty、fixed service 等很多隐含条件，但没有独立章节把它们做成“假设—理由—用途—如何测试”的索引。补一个 6–8 行紧凑表，比增加泛泛的 assumption 清单更合适。

### 4. 数学表达要“先给选择理由，再给式子和解释”

Team 15504 没有直接抛出复杂回归，而是先解释为什么 inclusion 是 binary classification、概率为何合适，再写总概率及 0.5 阈值，并说明三个分量分别代表什么。Team 15041 用表把模型输出转成可比较的分数和排名。评委评论还明确说，复杂但解释不清的模型不优于简单而完整的模型。

当前稿的式子和下标较密，已有自动编号，但没有一张只列真正使用变量的 notation table。建议加入 symbol、含义、单位/维度、出现在哪些式子的简表；每个模型小节先用一段话回答“为什么用这个模型”“它简化了什么”“怎样判定可行或不可行”，然后才给式子。

### 5. 验证要成为独立、可审计的证据，不只藏在数据段落里

评委看重模型验证，即使只是数值复现、历史数据回测或合理直觉。Team 15504 用历史 inclusion 模式检验；Team 14995 用替代模型、误差范围和稳健性比较来支持模型选择。

当前稿实际上有三类强证据：98.035% 的 route-hour 对账、capacity signatures 的匹配比例、432,768-case joint sensitivity；还有约束检查返回 UNVERIFIED 的逻辑。问题是它们散在 pp.3–6、pp.10–16 和 p.22，没有形成“Validation/Model evaluation”一页。补一张三行表即可：内部一致性、外部基准、情景/敏感性；每行写测试、通过情况、不能证明什么。

### 6. 图表必须紧邻解释，一张图只承担一个比较

评委评论明确指出：图表和文字应互相增强，看到图表后应立刻讨论其含义；需要解释的图不应孤立放置。Team 16226 的流程图展示全过程；Team 15041 的表直接给出跨城市比较。

当前稿的图本身清楚、配色克制、字号可读，但 PDF p.11 只有 Figure 1 与 caption（约 269 个字符），p.17 只有 Figure 3 与 caption（约 238 个字符），解释分别在下一页。建议缩小图或改排版，让“看什么 → 数字是多少 → 决策含义”出现在同一跨页。

另一个具体一致性风险：summary 的主结果是 class-specific 的 35.3–84.0% 减排，而 Figure 2/caption 展示 base generic hardware boundary 的 29.2–82.4%。两者都真实，但并排出现时容易被误读成矛盾。应明确标注同一边界，或把两组结果显示在同一比较表中。

### 7. 敏感性分析要指出“最要紧的参数”，而不是只展示大量情景

Team 14995 用 Monte Carlo 和多方法权重比较突出哪些指标改变会推翻结论。2024 评委评论建议识别关键参数，并把敏感性贯穿模型，而不只在末尾补一页。

当前稿虽有 432,768-case Cartesian audit，这是强项，但正文还需一句更直接的排序结论：range/request count 和 vehicle cost basis 对经济分数影响最大；baseline fuel mix 对排放分数影响最大。把“敏感性很大”改写成“决策在哪种条件下翻转”，更符合评委的决策导向。

### 8. Strengths/Limitations 与 Conclusion 是两个不同的收束动作

评委评论把 strengths/limitations 视为团队理解模型适用条件的证据；限制写出来不会扣分。结论则应回答具体 scenario questions，并保持全文逻辑闭环。

当前稿的标题为 “Sensitivity, limitations and decision boundary”，实际重点是缺点、缺口和 UNVERIFIED 状态；没有明确列出模型优势。文献后也直接进入 references，没有正式 Conclusion。应把 strengths/limitations 分开，并在正文末尾新增半页到一页 Conclusion，之后才放参考文献和 letter。

### 9. 论证顺序应先回答“所以怎么办”，再解释“为什么还不能更精确”

Outstanding 示例通常先给可操作结论，再说明模型边界。当前稿的透明性很强，但多段以“缺少 garage、age、winter、site power，所以无法认证”收尾，容易让读者把整篇理解成未完成。合理做法是保留同样的 caveat，但采用：

结果 → 解释 → 置信边界 → 下一步验证 → 决策影响

而不是让 caveat 成为每一段的终点。

尤其要解释：在 class-specific gross cost 比 normal renewal 高约 75.0% 的情况下，为什么仍建议启动 2033 conversion。建议把法律/政策目标、减排收益、可分期资本支出、grant 和最高可接受成本写成显式 decision rule；否则定量结果与 recommendation 之间会出现逻辑跳跃。

## 当前论文的修改优先级

### P0：提交前必须处理

1. 将 \teamnumber 的 00000 替换为真实控件号。
2. 新增 Assumptions and Justifications 表：假设、为什么合理、在哪个公式/筛选/敏感性中使用、失败后的影响。优先覆盖 service preservation、capacity proxy、normal-renewal comparator、exclusive electric accessories、no mid-duty refuelling、fleet bridge 和 missing site data。
3. 新增 Model Validation/Evaluation：把 route-hour 对账、capacity-cluster 复现、published-program arithmetic、MIP certificate 和 432,768-case sensitivity 汇成一张表，明确哪些通过、哪些只能给条件性结论。
4. 新增 Conclusions，明确回答四问，并给出 Vancouver/Chicago/London 的 final status、成本/减排主结果和 procurement gates。
5. 在 problem definition 后放一张 Task → method → result → validation 的四行映射表，直接证明四问均已响应。

### P1：结构重排以放大模型

6. 压缩 pp.3–6 的证据审计。正文保留决定模型可用性的数字和三段解释；参数逐项来源、异常记录更可留在 repository/算法说明中。目标是在 pp.4–5 前进入 modeling framework。
7. 增加紧凑方法流程图。输入（2023 service、fleet bridge、range/energy）→ screening（trip/block/capacity）→ cost/emissions（matched boundary）→ three-city/cohort model → decision gates。Team 16226 的官方示例提供了直接依据。
8. 加入变量表，只保留建模真正需要的符号；首次在公式中使用时再次解释单位。
9. 固定“一个基础模型，再扩展”的叙述：先用固定 service + normal renewal 定义比较基准，再依次加入 charging、winter、capital grants、regional economics 和 cohorts。现在这些元素都已存在，只是需要显性的层级。

### P1：排版与摘要

10. 重写 summary，使四问、三城、关键数值和决策在一页内自然可读；去掉 summary 中的引用编号，减少缩写和重复 caveat。
11. 调整 Figure 1/3 的 float 或尺寸，避免整页只剩图与 caption；图表后立刻写 2–3 句解释。Figure 2 的 29.2–82.4% 与 class-specific 35.3–84.0% 应在 caption 或同表行中区分。
12. 将“UNVERIFIED”的代码状态在正文改写为可读文字（例如 “not auditable from public evidence”），保留技术状态词可放附录或复现说明。

### P2：已有优势，建议保留

- 一页 Summary、目录、每页 Team/Page header、25 页正文 + 独立 AI 报告的版式符合现行硬规则。
- 来源 URL、年份、单位、边界、可复现脚本和测试是明显优势；不要为了“更像模板”删去证据链。
- 四图配色、坐标轴、图例与字体总体清晰，已经达到可读性要求。
- Letter 已用非技术语言给出数量、成本、充电和采购门槛，继续保留；可在开头更直接写出 requested decision。

## 证据边界与未完成项

- 2025 年没有取得任何获奖论文正文；Mathmodels 的会员门槛是官方明示，不应把训练机构宣传页、付费拼团或未标明控件号的副本当作可验证 Outstanding 全文。
- 2024 示例 PDF 的段页来自不同原稿，页眉、字号和行距并不完全统一，不能直接当作单篇论文模板；应以现行 instructions 的 12 pt、页眉、25 页和匿名要求为准。
- 本报告提炼的是公开材料与 COMAP 评委评论支持的规律。它不证明某一种版式本身能获奖，也不评价未读到的 2025 正文。
